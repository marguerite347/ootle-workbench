# Existing-catalog review

Run `node scripts/review-catalog.mjs --workbench-catalog /absolute/path/to/workbench/apps/remix-ide/src/app/plugins/ootle/ecosystem-resources.json` at the start of each daily maintenance run. Save the result in the run workspace. It enumerates reviewed project/submission records and both builder catalogs, deduplicates by resource identity and preserves known source links and prior review dates. It makes no network requests and does not mark anything fresh.

Use the existing public source readers, forum monitor and GitHub metadata/README/release reads for each queued resource. A recent-post lookback does not replace this queue. Include known demo/homepage/download destinations and original threads, since these can change independently. Record the read scope and actual content hash/revision; keep raw bodies outside public source.

`recordCatalogReview` in `sourceMonitoring.mjs` applies dated observations to `resourceReviews` in the existing `docs/ecosystem-source-registry.json` ledger. Failed reads retain the last successful source content and review date. A changed source hash queues copy, actions, Details, recording and provenance review. A successful fetch alone or an unchanged hash does not mark the editorial review complete. Set `reviewed` and `complete` only after actually completing the declared source scope; record partial coverage and retries otherwise. Synchronize the corresponding Workbench ledger/catalog after approved updates.

After discovering new availability, review the public destination and update every affected surface together. Preserve prior evidence and original-post links. Refresh footage when the available experience materially changes; old source footage is not a demonstration of a newly released app. Keep negative findings dated and limited to the sources checked. The fixtures in `server/test/sourceMonitoring.test.mjs` cover demo/release changes and blocked reads; they do not prove every future update will be detected.

# Dependency remediation evidence

## Follow-up — 2026-10-09

The current lockfile inventory contains 34 affected names out of 2,964 locked names, down from 80 after the first pass and 116 at baseline. These are package/advisory matches, not 34 demonstrated exploits. The first planning script skipped every multi-line dependency; the corrected tool evaluates each parent and refuses downgrades or incompatible major overrides. Yarn re-resolved vulnerable selectors within declared ranges, followed by reviewed parent-specific patch/minor overrides.

Unused npm-install-version (including its npm 4 dependency), Lerna publishing, Nx Cloud, local transformer model, request/RSS, obsolete Babel 6 presets/plugins and browserify reload dependencies were removed after checking source and configuration references. The Git UI had an undeclared dateformat dependency supplied incidentally by removed tooling; it is now declared directly. TOML used by the editor is 4.2.0; an older transitive TOML remains under the inherited Amp CLI. Normal Counter TOML and prototype-isolation smoke checks pass.

`dependency-paths.mjs` records a shortest path from each direct dependency to every remaining vulnerable version. A bounded webpack completion hook records exact versions included in emitted chunks; the existing analyzer was unsuitable because its asynchronous write could be truncated by process exit. CI uploads a commit-qualified report separately from deployed assets. Package presence is not proof of vulnerable-call reachability, and absence from the main bundle does not cover copied plugin applications. Raw advisory evidence and the parent upgrade plan are adjacent JSON files.

Nx now uses its local task runner with its daemon disabled by default; the web development server binds loopback. Lifecycle scripts remain disabled. The native companion has no npm dependencies. A vulnerable local development tool is not made safe by static deployment; do not interpret the report as a clean dependency audit.

Four additional parent overrides intentionally cross major versions after inspecting actual caller APIs: Bee uses Axios 1.20.0; IPFS uses parse-duration 2.1.9; github-base uses parse-link-header 2.0.0; Jayson uses UUID 11.1.1. Tests exercise Bee upload/download against a local fixture, IPFS timeout strings and client construction, normal/oversized pagination headers, and browser JSON-RPC request/response IDs. All four pass, as does the production bundle.

Exact-version evidence now finds only braces 3.0.3 and elliptic 6.6.1 among flagged versions in the main bundle. This does not clear the full lockfile: older Axios/UUID lines remain in other dependency paths. The remaining two packages have no advisory-free compatible release in the registry evidence used by the planner.

- `braces`: nested-pattern exhaustion remains an inherited library risk. The browser dependency enters through legacy deep-agent/glob and wallet storage code. The upstream Remix AI plugin is denied activation, the new Ootle agent service does not use that browser agent stack, and the companion accepts a file map rather than executing glob patterns. Build-side watchers and globbers still use inherited versions; the local toolchain is trusted, not a hostile-source sandbox. This is a mitigation and exposure assessment, not a claim that braces itself is repaired.
- `elliptic`: legacy EVM and Swarm dependencies retain this cryptographic implementation. New companion authentication uses Node/WebCrypto AES-GCM and does not use elliptic. The Workbench Tari path does not implement Ethereum signing. Replacing the inherited EVM cryptographic stack remains separate upstream maintenance; no blanket cryptographic safety claim is made for those features.

The other 32 flagged names are not present at vulnerable versions in the emitted main bundle. This does not prove they cannot be reached by copied plugin applications, CLI tools or tests. The report preserves every root-to-version path. Dev-server/Nx risks are reduced by loopback binding, disabled daemon/cloud cache, fixed CI commands, lifecycle-disabled installs and read-only CI; remaining local-tool advisories are unsuppressed. A zero-advisory upstream migration has not been completed.

## Rust maintenance assessment

`cargo tree --locked -i` confirms these exact paths under test tooling:

- `tari_template_test_tooling → tari_engine → tari_utilities → bincode 1.3.3`. The parent exposes blanket Serde-based binary serialization/deserialization in `message_format.rs`; substituting another format changes binary compatibility. [RustSec](https://rustsec.org/advisories/RUSTSEC-2025-0141.html) lists no patched version. Its alternatives require an upstream format/API migration, not a version override.
- `tari_template_test_tooling → tari_engine → wasmer → paste 1.0.15`, also through Wasmer compiler → libwild → linker-utils. [RustSec](https://rustsec.org/advisories/RUSTSEC-2024-0436.html) recommends pastey; both parent manifests must migrate the dependency alias. There is no patched paste release.
- `tari_template_test_tooling → tari_engine → wasmer → wasmer-derive → proc-macro-error2 2.0.1`. Wasmer's derive uses the attribute and abort macro for invalid ValueType layouts. [RustSec](https://rustsec.org/advisories/RUSTSEC-2026-0173.html) lists no patched release; replacing it requires changing the parent procedural macro and checking compile-failure diagnostics.

These remain unsuppressed maintenance warnings, not fixed defects. The release WASM dependency closure excludes all three. Existing security patches repair faster-hex/memmap2 and replace yanked yoke-derive; Linux CI run 37947266225 passed the real Counter engine tests, WASM and encrypted companion compilation. Its fresh Rust audit reports zero vulnerabilities and three unmaintained warnings, with no yanked or unsound warnings; see rust-audit-followup.json.

CI has read-only permissions and no application secrets, no persistent checkout credentials and no install scripts; only push artifacts have commit-qualified names. Static builds include hashes and local script SRI. Do not run development servers against untrusted network clients or build unreviewed forks with host secrets.

## November 17, 2026 scoped parser and Forge update

The current npm advisory inventory matches 11 package names in the root lock graph. This is an inventory, not a count of demonstrated exploits. ## November 19, 2026 heapless repair

The fresh audit of both Counter lockfiles found nine unsoundness advisories in heapless 0.8.0, RUSTSEC-2026-0574 through 0582, published November 18. The dependency is used by faster-hex 0.10.1 under gix-hash and the pinned Tari engine test tooling. The release WASM normal-dependency closure excludes this chain. This limits its scope but does not make the development dependency acceptable or waive the audit gate.

A reviewed parent manifest patch selects the official repaired heapless 0.9.4 release while retaining faster-hex 0.10.1 and the existing Tari APIs. Both starter and downloadable example carry identical source/license-preserving patches; the embedded starter includes all build inputs and licenses. The patched parent's minimum Rust version is accurately set to 1.88. Registry provenance and patch scope are recorded in vendor/SECURITY_PATCHES.md.

Focused allocation-enabled and no-allocation tests passed hexadecimal encode/decode round trips, integer byte boundaries and malformed-input rejection. Embedded-template parity and the existing audit-gate regression tests pass locally. Real Linux engine tests, WASM builds and fresh audits remain required CI acceptance for this change; they are not inferred from the focused tests. The gate is unchanged and continues to reject unsound findings. Existing unmaintained dependency warnings remain separately tracked.
